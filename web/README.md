# ice3tier WebUI

controller 的管理界面。它只和 controller 的管理 API 说话（见 [`docs/admin-api.md`](../docs/admin-api.md)），和 API 同源，每个请求带 `Authorization: Bearer <管理令牌>`。界面有简体中文和英文两种语言（见「界面上的文字」）。

技术栈：React、TypeScript、Vite、TanStack Query、React Router、Tailwind、shadcn/ui 风格的部件（Radix）、React Flow（访问关系图、拓扑）。包管理用 `pnpm`。

## 准备

- Node 22 或更新，`pnpm`。
- 安装依赖：

  ```sh
  pnpm install
  ```

## 开发

界面要有一个跑着的 controller 才有数据。先在仓库根目录构建并启动一个：

```sh
cargo build --release -p i3t-controller-bin -p i3t
target/release/i3t-controller --data-dir /tmp/i3t-dev --public-addr 127.0.0.1:20331
```

第一次启动时它会打印管理令牌，只显示这一次，登录界面时要填。然后在 `web/` 里：

```sh
pnpm dev
```

开发服务器（默认 `http://localhost:5173`）把 `/api` 开头的请求代理到 controller 的管理端口，所以浏览器看到的仍然是同源，controller 不需要发 CORS 头。

**controller 的地址由环境变量 `I3T_CONTROLLER` 决定**，默认是 `http://127.0.0.1:20332`（controller 默认的管理地址）。controller 在别处时：

```sh
I3T_CONTROLLER=http://127.0.0.1:20432 pnpm dev
```

也可以把 `.env.example` 复制成 `.env.local` 再改，不用每次写在命令行上。

要看节点加入之后的样子，照界面上"添加节点"给出的命令，在另一个状态目录里执行：

```sh
export I3T_STATE_DIR=/tmp/i3t-dev-node1
echo <注册令牌> | target/release/i3t join
target/release/i3t run
```

| `src/auth/`       | 登录页和登录状态（管理令牌存在浏览器里）                                                                                                                               |
| `src/pages/`      | 每个页面一个目录                                                                                                                                                       |
| `src/components/` | 页面共用的部件；`ui/` 下是最基础的那一层                                                                                                                               |
| `src/access/`     | 访问关系图的数据整理和几何，纯函数                                                                                                                                     |
| `src/topology/`   | 路由视图的数据整理：路由矩阵变成拓扑图的点和线、一条路的几种说法、路径诊断里一个方向怎么说、地址里选中的那一对节点，纯函数                                             |
| `src/lib/`        | 校验、地址段的计算、给用户执行的命令、时间和字节数的写法、版本号的比较、节点更新情况的说法、用量和监听状态的说法、独占 TCP 的说法等                                    |
| `src/i18n/`       | 界面上的全部文字，每种语言一个目录；语言的选择和切换。组件里不直接写界面文字                                                                                           |
| `src/test/`       | 单元测试的准备和假的管理 API                                                                                                                                           |
| `e2e/`            | Playwright 的端到端测试和截图                                                                                                                                          |
| `screenshots/`    | `pnpm screenshots` 截下来的每个页面，只在本机看，不提交                                                                                                                |

几条约定：

- 管理 API 变了，`src/api/types.ts` 和 `src/api/endpoints.ts` 要跟着改，它们是照着文档手写的。
- 提交之前的校验（`src/lib/validate.ts`）和 controller 的规则一致，只是为了早一点指出错误；controller 拒绝时显示它给的原因。
- controller 还没有接口的页面（现在只剩连通性测试）是"计划中"的说明页，不放假数据。接口有了之后，在 `src/routes.tsx` 里把对应的那一行换成真正的页面。拓扑、路径诊断和节点更新（设置里的一个分区）就是这样填上的。
- 界面自己的版本号只有一个来处：`package.json` 的 `version`（每次迭代由仓库的脚本改它）。`vite.config.ts` 在构建时把它作为常量 `__APP_VERSION__` 写进代码，`src/lib/version.ts` 的 `WEB_VERSION` 是唯一读它的地方；运行时不读 `package.json`。顶栏标题后面的版本号和设置的「关于」写出 controller 的版本和界面的版本；两者不一样时版本号变成琥珀色，已知有比 controller 新的正式版时版本号上有一个小点，点了去「节点更新」。
- 节点的更新情况（有新版本、正在更新、等什么、失败、不能自己更新的原因和做法）在节点列表、节点详情和设置里用同一套说法，都出自 `src/lib/nodeUpdate.ts`。
- "已用多少、上限多少"（凭据的流量、出口的配额）都出自 `src/lib/usage.ts`：不到八成是中性的深灰，八成以上琥珀色，用完红色，没有上限时不画进度条。字节数一律经 `formatBytes` 写（按 1024 进位），输入上限时的单位（MB、GB、TB）也按 1024 算。
- 一个监听（代理监听器、端口转发的监听一侧、节点自带的回环入口）现在怎么样，在监听器页、端口转发页、节点详情的「监听」和总览里用同一套说法，出自 `src/lib/listenState.ts`。端口写 0 的转发，列表里写节点挑定的端口。
- 凭据的删除分两步：第一次是吊销（危险确认，记录留着，看得到用过多少），对吊销了的再删一次才彻底删掉（普通确认）。注册令牌默认只列还能用的，「全部」里有最近 30 天用掉和过期的，写着是哪个节点用的。
- 操作记录按网络、操作、对象筛（交给 controller，一页一百条往前翻），搜索只在取回的记录里找；条件写在地址里。记录里提到的东西做成链接：列表页带着 `focus=<编号>` 打开，那一行亮出来；东西已经删掉了的，页面上说一句。
- 一条路的细节（直连是局域网、IPv6、端口可达还是打洞；经 relay 时第一段走 UDP 还是 TCP）在节点的路由表、路由矩阵的格子和路径诊断里用同一套说法，出自 `src/topology/route.ts`。比界面旧的 controller 不写这几个字段，界面就不写细节。
- 拓扑的实时图和路由矩阵是同一份数据（`GET /networks/{network}/routes`）的两种写法；路径诊断每次都去问两端（`GET /networks/{network}/path`，最多等 3 秒），所以不轮询，页面上有"再问一次"。两页之间、和两种写法之间，选中的那一对节点写在地址的 `a`、`b` 里跟着走。现问到的方向还有发送方的选路模式、原因和它考虑过的候选路径（代价、每一段的延迟、抖动、丢包、relay 的负载），在两个方向的卡片下面各一张表。拓扑的第三个标签页"骨干"是 relay 之间的延迟矩阵（`GET /networks/{network}/backbone`），和路径诊断一样每次现问节点、不轮询。
- 分组（`docs/admin-api.md` §18）只能从已有的里选：节点、注册令牌上用 `GroupPicker`（`src/components/groups.tsx`）：框里是选中的分组，点开是一个能搜索的列表，每行一个分组、它有几个节点、一个勾选框，勾上、取消都不收起列表；搜索只是筛选，不会因此新建分组，旁边一个安静的链接去分组页。分组到处是同一个样子（`GroupChip`：分组的图标加名字）；规则的两头也只从已有的分组里选。内置的 `All` 总在最前面、勾着、移不掉；认它看分组引用上的 `builtin`，比 0.1.8 旧的 controller 不给这个字段，这时按名字认（`isAllGroup`，`src/lib/groups.ts`）。请求里一律写分组的编号，地址里也写编号（节点列表的 `group`、总览的 `group`、分组页的 `focus`），改名之后链接还是同一个分组。删除分组之前现取这个分组（`GET …/groups/{group}`），确认框写它从几个节点上移除、几条规则一起删掉。分组的错误按 `code` 和 `what` 写（`src/api/client.ts`），名字的写法不对按 `what` 写在名字下面（`groupNameFailure`）。
- 节点更新的暂停按网络算：同一个版本在几个网络里被暂停时，设置里是一条横幅，写明是哪几个网络，"继续"一次继续全部。
- 独占 TCP（节点对的一项设置）在节点对页和节点详情的「独占 TCP」标签页里用同一套说法，出自 `src/lib/lanes.ts`。起不起作用按 controller 给的原因码（`lane_effect.blocked`）用界面自己的话写，每个原因带修好它的那一步（在哪个节点上启用 relay、填 TCP 地址、更新节点、检查访问）；controller 的 `summary` 只在原因码不认识时原样显示。一对节点的数由两边各自报的合起来：在用的连接两头都算，取大的；空闲的按停在哪一边相加；回退和拨号失败相加。没有节点报上来时不画计数，也没有详情。节点详情的「独占 TCP」标签页只在和哪个对端打开了独占 TCP 时出现。路由视图不因独占 TCP 改变（共用的连接和它的路照常保留），节点对页上说一次。

## 界面的样子

目标是一个安静的工具界面：干净、留白、信息在前。结构靠对齐、留白和字号，而不是框线和底色；颜色只在需要人注意的地方出现。新页面照下面做，出来的样子就和别的页面一致。

### 记号（`src/index.css`，只在这一处定义）

| 类别   | 取值                                                                                                                                                                                                                                                                                 |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 中性色 | 面板和控件白（`background`、`card`），整页的底和画布浅灰（`canvas`，`sidebar` 是它的别名），悬停和小块底色（`muted`），细线（`border`），输入框的边（`input`）。字三档：正文 `foreground`，次要 `muted-foreground`（对白底 5.3:1），`faint` 只给图标、复选框的边和占位，不给要读的字 |
| 强调色 | 一个蓝（`primary`）：每页最多一个的主按钮、选中、键盘焦点、文字链接。`accent` 是它很淡的那一档，给选中的行、选中的格子。侧栏、标签页、分段切换的选中用中性的灰和黑，不用蓝                                                                                                           |
| 状态色 | `ok` 绿、`relay` 紫、`warn` 琥珀、`danger` 红、`idle` 灰。只出现在 8 像素的圆点、图上的线、矩阵格子很淡的底色和要人注意的那一句话上。`StatusText`：正常的字是黑的；warn 加粗、字仍是黑的；只有 danger 是红字                                                                         |
| 字     | 系统字体（不打包、不联网取）。字号只有这几种：12（表头、说明、徽标）、13（次要的字、提示）、14（正文、表格、控件）、16（分区标题）、20（页面标题）、28（总览上的数）。粗细只有 400、500（名字、按钮、标签）、600（标题、数）。表格里的数一律等宽数字（`table` 上全局设好）           |
| 间距   | 4 的倍数。页面左右 32（≥1280 时 40），页面标题和内容之间 32，同一页的分区之间 40–48，分区标题和内容之间 12，表格行上下各 12                                                                                                                                                          |
| 圆角   | 4（徽标、分组、矩阵格子）、6（按钮、输入框）、8（菜单、弹出层、图上的点）、12（对话框）                                                                                                                                                                                              |
| 阴影   | 只给浮在页面上的东西：菜单、弹出层、对话框、通知（`shadow-pop`）。页面里的东西不投影                                                                                                                                                                                                 |
| 图标   | lucide，线宽统一 1.75；按钮和导航里 16 像素，字里 14 像素；颜色跟着字或者更淡（`faint`）                                                                                                                                                                                             |

拓扑图、访问关系图的颜色是具体的值（画图的库要），在 `src/topology/colors.ts` 和 `src/access/colors.ts`，和上面的状态色是同一套，改一边要改另一边。

### 部件的规矩

- **总览**：整个面板是访问地图（`src/access/map.ts` 整理数据，`pages/overview/AccessMap.tsx` 画）：左边是看的那一个——一个节点，或者一个分组，点它换一个；中间是和它有关的规则，一条一个胶囊（名字、双向或单向，停用的是虚边灰字）；右边是规则另一头的分组和它有几个节点，点了换成看那个分组。连线是虚线，顺着访问的方向流动，双向的两条一来一回；启用的绿、停用的灰且不动。左上角换视角（节点、分组），看哪个写在地址里（`view`、`node`、`group`：分组的编号）。右上角一句话说整个网络的状态，有问题时点开是那几件事和去处理的链接（`pages/overview/Attention.tsx`）。节点不足两个时整页是引导。
- **国旗**：节点的公网地址所在的国家或地区（`Node.country`，controller 查自带的离线地址库得出）在节点列表的虚拟 IP 左边画一面 16 像素的圆形国旗（`src/components/flag.tsx`）。旗子是 `public/flags/` 里的 SVG（[circle-flags](https://github.com/HatScripts/circle-flags)，MIT，许可在同一个目录里；只放了两个字母的国家代码那 265 个，共约 180 KB），按需取、不联网。不用国旗表情：Windows 上的浏览器不画。节点列表一行 88 像素高；"版本"一格两行：i3t 的标志和版本号，下面是系统的图标（`src/components/os-icon.tsx`：Linux 和苹果的图形出自 Simple Icons，CC0；Windows 的四个方块自己画）和平台的名字。
- **亮色和暗色**：顶栏右上角的外观菜单里切换，跟随系统（默认）、亮、暗三种，记在浏览器里（`localStorage` 的 `i3t.theme`）。暗色是 `<html>` 上的 `dark` 类，全部颜色和阴影在 `index.css` 的 `.dark` 里换一套，部件不写死颜色；`index.html` 里一小段脚本在画出页面之前定下来，打开时不闪白。画图的库要具体的颜色值，关系图和拓扑图的线色由 `useEdgeColors`、`useLineColors` 按当前的亮暗给。
- **弹出的东西**：菜单和弹出层从触发它的按钮那一侧长出来（淡入、放大、朝外挪几个像素），关上时缩回去淡出，见 `index.css` 的 `pop-in`、`pop-out`。
- **外壳**：整页是一层浅灰的底（`canvas`），侧栏和顶栏都没有自己的底色和边线，直接坐在它上面；正文是底上面一块白色的大圆角面板（`AppLayout`），面板不动，内容在里面滚动。侧栏是左边整个窗口高的一列：顶上是标志和收起按钮（收起时只剩标志，悬停变成展开的按钮），下面是导航，分四个区（不带标题的四项、接入、诊断、管理），当前那一项是一块浮起来的白。顶栏在侧栏右边、面板上面：左边总是写着「控制台」和界面的版本号（悬停写出两边的版本；两边不是同一次构建时琥珀色，有新版本时右上角一个小点、点了去「节点更新」）。每个页面的标题区在正文面板的最上面（`PageHeader`）：22 像素的粗体标题，下面一行 14 像素的灰色副标题说这一页是做什么的，右端是这一页的按钮；总览没有标题区，节点详情自己画：左边一块 52 像素的方块画它的系统，右边第一行是 22 像素的名字、改名的铅笔、角色徽标（带图标的大一档），第二行 13 像素的灰字写状态（圆点加在线、离线）、虚拟 IP、域名，细竖线隔开，点值就复制。右上角是外观、语言和当前网络（和图标按钮一样没有底和边，菜单里切换网络、网络设置，隔一条线是设置和退出登录；管理员没有名字和头像，不另放账号按钮；新建网络只在网络页上）。尺寸照着参考的界面：侧栏 208 像素宽，上下留 18、左右留 14，分区之间 22；导航一行 38 像素、14 像素的字、18 像素的图标、图标和字隔 11；分区标题 11 像素。顶栏 60 像素高、左右留 24，「控制台」18 像素；页面标题 22 像素粗体，副标题 14 像素；右上角的图标按钮 32 像素见方，彼此隔 8 像素。菜单 14 像素的字，32 像素一行。
- **页面**：`<Page>` 加 `<PageHeader>`。内容铺满面板，不限制宽度。`PageHeader` 是面板顶上的一条，下面一根线横贯面板；标题下面一般不写说明（见「界面上的文字」），右端最多一个主按钮，再加一两个次要的。
- **不写死高度**：高度由内容和留白撑出来，或者由弹性盒子分（`flex-1`），不写 `h-[600px]` 这样的值，也不拿视口的高度去算。要占满剩下的地方的内容（关系图）：页面写 `<Page fill>`，那一块用 `<Canvas>`。整个界面只有外壳的最外层用了一次视口的高度。图标、圆点这类固定大小的小东西不算。
- **分区**：`Card` 现在是一个没有框的分区，`CardHeader` 是 16 像素的标题、右端一个这个分区自己的动作；说明只在标题之外还有信息时才写。分区里的列表以一条细线开头（`border-t`），行与行之间细线（`divide-y`）。普通的分区不加边框、底色或阴影。一页里几块信息并排放的时候（节点详情的概览）用有框的卡片 `BoxCard`：圆角、细边框，`BoxCardHeader` 是 48 像素高的标题条（15 像素半粗、下面一根线），内容左右留 20 像素；"名字：值"的列表用 `DetailList` / `DetailRow`（`src/components/detail-list.tsx`）：左边图标和名字（14 像素，正文的颜色），右边灰色的值靠右，最右是这一项的按钮（改、复制，一直看得见）；行高至少 44 像素，细线横贯整张卡片。时刻写"完整的日期和时分 · 多久以前"（`DateTimeValue`）。节点详情的概览两栏一样宽：左边是信息卡，没有标题条（名字在页面标题上），一行一项：虚拟 IP、公网地址、域名、主机名、地区（国旗和国家名）、系统、公钥、加入时间、最后在线、版本、配置；右边是分组（不套卡片：标题、一句它管什么、选分组的框），下面是一直展开的「高级」（选路模式、路径限制、只拨出、指定的中继，一行一项，名字左边、控件右边）。中继、出口、端口转发目标各有一个标签页，每页一张卡片：顶上是图标、名字、一句话和开关（启用之后开关左边一个「修改」），下面是现在的设置，和信息卡一样一行一项；修改的表单、怎么声明也在这张卡片里。这几页不铺满整个宽度，开关才对得上名字。
- **表格**：`Table`、`Th`、`Td`、`Tr`（`src/components/table.tsx`）。不放在框里；第一列是名字，数右对齐，操作在最后一列的「⋮」菜单里。表格向两边各伸出 12 像素，字和页面标题对齐。上面的搜索、筛选用 `Toolbar`，下面的共几项、翻页用 `TableFooter`，常驻的一句说明用 `TableNote`。一行的原因和下一步写在它下面单独的一行里，不挤进状态格。
- **按钮**：`primary` 每页最多一个；`outline`（默认）是次要动作；`ghost` 给工具栏、行内、菜单触发和"查看 ›"这类去别处的动作；`link` 给句子里的动作。破坏性的动作放进菜单最后，红字；只有"删除网络"这种整页唯一的危险操作才用 `danger-outline`。
- **状态**：`StatusText`、`StatusDot`、`OnlineDot`（`src/components/status.tsx`）。在线是实心绿点，离线是空心灰圈，紧贴在名字前面。不要用彩色的字写"在线""正常""已启用"。
- **徽标**：`Badge` 默认是浅灰底的小字（协议、角色、"自带"）；`outline` 是细框（内置、默认）；彩色的只给要注意的（`warn`、`danger`）和"现问到"这类来源。
- **提醒**：`Notice` 的 `info` 是一句灰色旁注，不铺底；`warn`、`danger` 才铺很淡的底色。不要在页面里堆提醒框，能写成表格下面的一句说明的就写成说明。
- **空、加载、出错**：`EmptyState`（淡灰的图标、一句话、一个按钮）、`NoMatches`、`ErrorState`（按错误码写原因，controller 的原话在下面一行作补充）、`SkeletonRows`、`SkeletonBlock`。不要再给它们套框。
- **较长的解释**：`InfoTip`（名字旁边一个小图标，悬停或聚焦时显示）或者 `<details>`。
- **表单**：对话框里用 `FormDialog` 和 `Field`；单选用 `RadioCards`（没有框的选项列表）；输入框的外观是 `fieldBase`，自己画的输入框（搜索、选分组）也用它。
- **图**：React Flow 的画布放在一块浅灰（`bg-sidebar`）的圆角区域里，不加边框；图上的点是白底细框，离线的虚线框；选中的用强调色的框。图例写在画布下面，一行灰色小字。

### 做和不做

- 做：先想这一页的人来是为了看什么，让它是页面上最显眼的东西（总览是访问地图和右上角那句状态，诊断是"直连 1 ms"）；次要的说明用灰色 13 像素。
- 做：用留白分组，用一条细线分开同一个列表里的行。
- 做：操作可以安静（`ghost`、悬停才出现的排序箭头），但要能用键盘到达、有可读的名字；悬停才出现的东西在键盘聚焦时也要出现。
- 不做：框里套框、给分区加边框或阴影、给标题加彩色图标底圈、整列彩色的字、蓝色的分组、等宽字体的分组名。
- 不做：新的颜色、字号、圆角或阴影。需要的时候先改 `index.css` 和这一节。

### 怎么写

1. **名字**是短的名词短语。**按钮**是动词，或动词加名词（"新建规则""Create rule"），不写"确定""提交"。**表头**一两个词。
2. **页面**只有标题。标题之外还有信息时才加一行，大多数页面没有。分区标题同样。
3. **说明**只在三种情况写，一行：防止填错；后果不明显（破坏性的操作、只显示一次的秘密）；某个设置要另一件事成立才起作用。值得留的长解释放进 `InfoTip` 或 `<details>`。拿不准就删。
4. **不对读者说话**：不写"请""你可以"，不写理由和安慰，不重复屏幕上已经有的东西。
5. **空状态**一句"还没有 X"加一个动作。**出错**说是什么情况，给重试；controller 的原话只作补充。
6. **带数据的句子**先说对象和状态（"hk-1 离线""hk-1 offline"），细节留给它链接的页面。
7. **确认框**的标题是动作加对象（"删除节点 laptop？"），正文只写不明显的后果，最多两短句，确认按钮写动作。**通知**写对象和结果（"节点 laptop 已删除""Node laptop deleted"）。
8. **标点**：一句话的（标签、按钮、表头、说明、通知、空状态）不加句号；两句以上每句都加。英文用句首大写（sentence case）。中文里汉字和数字、英文之间空一格。
9. **带参数的句子**写成函数，量词、单复数、语序在各语言的函数里处理。组件里不拼句子，不写"和""、"这类连接词：并列的名字用 `formatList`，两句接起来用 `t.common.sentences`。
10. **数、字节、日期、时间**只经 `src/lib/format.ts` 和 `src/lib/time.ts` 写，它们按当前语言（`Intl`）写。

### 语言

- 第一次打开时按浏览器的语言偏好（`navigator.languages`）挑一种有的，都没有时用英文。登录页右上角和顶栏右上角的语言菜单里都能换，选择记在浏览器里（`localStorage` 的 `i3t.locale`）。
- 换语言不刷新页面：`t` 就地改写，应用的根组件订阅语言（`useLocale`），整棵树重新渲染，填了一半的表单、展开的行都留着。`<html lang>` 和标签页的标题跟着变。
- 所以不要在模块加载时就把一句话取出来存着（`const LABEL = t.nodes.title`）：在渲染时读，或者写成取值函数。`src/i18n/live.test.ts` 检查这一点。自己缓存了文字的地方（`useMemo`、画图的库的节点）把 `useLocale()` 放进依赖里。
- 有些文字来自 controller 或节点，是中文写的（错误的原话、操作记录的说明、换路的原因等）。接口给了错误码、操作、状态这类结构化的字段时，界面按它们用自己的话写，原话只作补充；只给了一句话的，原样显示。
- 测试固定用简体中文（`src/test/setup.ts`），期望的文字从目录里取（`t.…`），不在测试里抄界面上的字；端到端测试同样从 `src/i18n/zh-CN` 取。

加一种语言：

1. 照着 `src/i18n/en/` 写一个目录，每个分区写成 `export const nodes: Messages['nodes'] = { … }`，在它的 `index.ts` 里合成一个对象。少一个键、多一个键、参数不对都是编译错误。
2. 在 `src/i18n/index.ts` 的 `LOCALES` 里加一行：代码（BCP 47，也是 `Intl` 和 `<html lang>` 用的）和它用自己的文字写的名字。
3. `pnpm typecheck` 和 `pnpm test`：`src/i18n/i18n.test.ts` 查空的字符串、函数写不出话、各语言的键不一样。英文和中文都比较短，换一种语言要在 1280 和 1024 宽各看一遍页面。

## 检查和测试

```sh
pnpm typecheck    # TypeScript
pnpm lint         # ESLint
pnpm test         # 单元测试和组件测试（Vitest + Testing Library，jsdom）
pnpm e2e          # 端到端测试（Playwright，无头 Chromium）
pnpm screenshots  # 截一遍每个页面：中文的放到 screenshots/，英文的一组放到 screenshots/en/（不提交）
```

**单元测试**和被测的代码放在一起，文件名是 `*.test.ts` / `*.test.tsx`。组件测试不连真的 controller：`src/test/harness.tsx` 里的 `fakeApi` 接住 `fetch`，按"方法 路径"应答。改代码时可以用 `pnpm test:watch`。

**端到端测试**用的是真的程序：每个测试文件自己启动一个全新的 controller（数据在临时目录里），用 `pnpm build` 的产物作界面，把界面上给出的加入命令原样交给 shell 执行，结束时把 controller 和节点都停掉、临时目录删掉。所以运行之前不需要开着什么，但要先构建好 Rust 的程序。

`pnpm e2e` 跑六个文件：`flows.spec.ts`（从空的 controller 开始的主要流程）、`routes.spec.ts`（三个真的跑着、互相连过的节点：拓扑的实时图、路由矩阵、路径诊断）、`updates.spec.ts`（节点更新，发布源是一个本机目录：换发布源、立即检查、节点上的标记和做法、确认框、全部更新之后一个节点真的换成新版本重启、一个自检不过的版本被暂停、继续）、`limits.spec.ts`（限额、用量和监听的状态，流量真的经两个跑着的节点走：凭据经要求凭据的监听器用过之后有用量、改上限让它用完、吊销、彻底删掉；出口配了配额、下载之后有用量；端口写 0 的转发显示节点挑的端口并且连得通；监听在被占用的端口上的转发显示端口被占用；操作记录的筛选和链接）、`lanes.spec.ts`（独占 TCP，三个节点都在本机回环上：一个是 relay、TCP 地址是它在回环上的节点端口；在界面上把一对设成"总是用"，看它生效、哪一边拨号；经一条端口转发真的走流量之后有在用的连接、详情里有字节数，节点详情的「独占 TCP」里有这一行；改回"不用"；两个都不是 relay 的一对写着为什么不起作用、去哪里启用 relay）、`groups.spec.ts`（分组，两个真的跑着的节点在本机回环上，经一条端口转发真的取东西：分组页上新建分组、名字的写法不对和重名都说清；在节点页上把节点放进分组；停用默认规则之后不通，在两个分组之间写一条规则之后通；分组改名之后照样通；删除分组时确认框写着它从几个节点上移除、几条规则一起删掉，删掉之后又不通；注册令牌带着分组，用它加入的节点就在那个分组里）。

`limits.spec.ts` 下载的目标是测试进程自己开的一个 HTTP 服务，监听在这台机器的私有 IPv4 地址上，出口打开"允许访问本机局域网"之后把它当局域网目标，不连外网。机器上没有私有 IPv4 地址时，要它的几项测试跳过。

节点更新要几样平时没有的东西：一把测试用的发布签名钥匙，认这把钥匙的 controller 和节点（`I3T_RELEASE_EXTRA_KEY`），版本号高一级的节点程序（`I3T_TEST_VERSION`），签清单的 `i3t-release`（见 `docs/releasing.md`）。`pnpm e2e:kit` 把它们编好，放在 `web/.e2e/release-kit`：

```sh
pnpm e2e:kit                             # 在 web/ 里；要能编译 Rust，第一次要几分钟
pnpm exec playwright install chromium    # 只在第一次
pnpm e2e
```

`pnpm e2e:kit` 默认编译这个仓库的源码，目标目录是 `target/e2e-web`。`I3T_SOURCE` 可以指向别的源码目录（例如 `git archive HEAD` 导出的一份），`CARGO_TARGET_DIR` 换目标目录，`I3T_RELEASE_KIT` 换放的位置。

`i3t-controller` 和 `i3t` 从哪里找：环境变量 `I3T_BIN_DIR` 指的目录；没设时依次试 `web/.e2e/release-kit/old`、`target/agent-web/release`、`target/release`、`target/lead/release`，用第一个两样都在的。节点更新的测试和截图总是用 release-kit 里的那一组。

测试里的 controller 一启动就把发布源换成一个空目录：测试不连外网，节点也不会被真的发布更新掉。每个节点跑的是它自己的一份程序文件，自己更新的节点换掉的只是那一份。

端到端测试在简体中文下跑（浏览器语言 zh-CN），界面上的字从 `src/i18n/zh-CN` 取，不在测试里抄；`flows.spec.ts` 里有一段在应用里换成英文再换回来。截图先截一遍中文的全部页面，再用浏览器语言是 en-US 的页面截英文的一组（长度最要紧的那些页）。

`pnpm e2e` 和 `pnpm screenshots` 都会先执行一次 `pnpm build`。截图也要 release-kit：发布源上有一个用测试钥匙签的新版本，节点更新的页面才有东西可看。失败时的截图和过程记录（trace）在 `test-results/` 里，后者用 `pnpm exec playwright show-trace <trace.zip>` 打开。

## 构建

```sh
pnpm build
```

产物在 `web/dist/`：一个 `index.html` 和 `assets/` 下带哈希的文件，全是静态文件。

## controller 怎么提供界面

界面由 controller 自己从管理端口（默认 `127.0.0.1:20332`）提供，不需要另外的 Web 服务器。`/api/v1` 之外的路径取静态文件；不是文件的路径一律回 `index.html`，交给前端的路由。静态文件不需要管理令牌，里面没有任何数据。

界面的文件有两个来路：

1. **编进 controller 的可执行文件**（正式发布是这样）。构建 `i3t-controller` 时，如果 `web/dist` 存在，里面的文件会被打进可执行文件，运行时不需要再带着它。所以要先构建界面，再构建 controller：

   ```sh
   (cd web && pnpm install && pnpm build)
   cargo build --release -p i3t-controller-bin
   ```

   构建 controller 时没有 `web/dist` 也能构建成功，只是这样的 controller 不带界面，打开管理地址看到的是一页说明。

2. **运行时用 `--static-dir` 指定一个目录**。给了就用这个目录，而不用程序自带的那一份。适合改界面时反复看效果（`pnpm build` 之后刷新页面就是新的，不用重新编译 controller），或者想换一套界面：

   ```sh
   i3t-controller --data-dir <数据目录> --public-addr <主机:端口> --static-dir web/dist
   ```

   目录里必须有 `index.html`，否则 controller 启动时就报错。

管理端口默认只在本机可达。要从别的机器打开界面，用 SSH 端口转发（`ssh -L 20332:127.0.0.1:20332 <controller 所在的机器>`），然后访问 `http://127.0.0.1:20332`。
